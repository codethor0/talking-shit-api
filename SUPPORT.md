# Support

Talking Shit API is an open-source project maintained on a best-effort basis.

## Bugs

For reproducible defects, open a bug report and include the smallest request or command that demonstrates the problem, the expected behavior, and the version or commit you tested.

Do not include credentials, secrets, personal data, or private production data.

## Feature requests

Use the feature request form for proposed API behavior, new categories, developer integrations, or repository improvements.

Changes that add persistence, authentication, arbitrary user text, outbound runtime calls, or runtime dependencies require explicit architecture review before implementation.

## Security

Do not report suspected vulnerabilities in a public issue. Follow `SECURITY.md` and use GitHub private vulnerability reporting.

## Service expectations

The public API is provided without an uptime or support SLA. The project intentionally avoids paid infrastructure and external runtime services so the operating model can remain small and sustainable.
